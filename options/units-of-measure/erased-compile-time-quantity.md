# Units Of Measure — Choice: erased-compile-time-quantity

> **The default choice for the `units-of-measure` decision** (see [README.md](./README.md) for the
> decision and the requirements a choice must satisfy). It pins the concrete surface and semantics of
> the optional dimensional-analysis layer that realizes the units-of-measure capability's requirements
> that a unit be checked at compile time, that a dimensional mismatch be a compile-time error, and that
> the whole apparatus be erased before emission without altering the numeric core.
>
> Units are a **compile-time-only verification layer**: they are checked and then erased before a
> single byte is emitted, so tuning this choice does not alter any component's bytes. A program with
> every unit stripped compiles to the identical component and runs identically — this is the
> meaning-preserving, discharge-does-not-change-bytes discipline (verification-layers.md) applied to
> dimensions.

## The shape in one line

A **quantity** is a value of the type `(Qty T u)`: an underlying numeric value of type `T` (any type
the numeric model admits — `Int64`, `Float64`, a `(UInt N)`, a rational) carried together with a
**compile-time unit** `u`. The unit is a compile-time value, not runtime data; `(Qty T u)` is an
ordinary type-constructor application, exactly as `(Int N)` is the integer constructor applied to a
compile-time width; and the compiler checks that the units of every arithmetic expression compose
consistently and then **erases** `Qty`, so the emitted value is just a `T`.

## Units form a free abelian group over named base units

A **unit** is a compile-time value in the free abelian group generated by a set of **named base
dimensions**. The group operations are the whole surface a program uses to build a derived unit:

| Form | Meaning | Example |
|---|---|---|
| `Unit.one` | the dimensionless unit (the group identity) | a plain count, a ratio |
| `(Unit.base name)` | a base dimension named by a `Symbol` | `(Unit.base #"metre")`, `(Unit.base #"second")` |
| `(Unit.* a b)` | the product of two units | `(Unit.* metre metre)` = area |
| `(Unit./ a b)` | the quotient of two units | `(Unit./ metre second)` = velocity |
| `(Unit.^ a n)` | a unit raised to a compile-time **integer** power `n` (may be negative) | `(Unit.^ metre 2)` = area, `(Unit.^ second -1)` = frequency |

Because the group is **abelian and free**, two units are the **same dimension** exactly when every
base dimension appears to the same integer exponent — order of multiplication does not matter,
`(Unit.* a b)` = `(Unit.* b a)`, and a base and its inverse cancel, `(Unit.* u (Unit.^ u -1))` =
`Unit.one`. A unit's **canonical form** is the multiset of `(base ↦ exponent)` pairs with every
zero-exponent base dropped, so dimensional equality is decided by comparing these canonical exponent
maps — a pure compile-time computation, no solver. This is the F#-units model (a free abelian group
over base units) expressed in Cadenza's own compile-time-value machinery rather than as bespoke
compiler syntax.

Base dimensions are named by `Symbol`s (`options/symbol-interning/`), so a program (or a prelude
module) declares its own base dimensions — `metre`, `kilogram`, `second`, `ampere`, … — and builds
derived units from them. The layer fixes the *algebra*, not a privileged SI vocabulary; a build's
prelude MAY supply the SI base dimensions and common derived units (`newton` = `kg·m·s⁻²`) as ordinary
definitions, exactly as `Int8` is an ordinary alias for `(Int 8)`.

## Constructing and observing a quantity

- `(Qty.of x u)` attaches unit `u` to a numeric value `x : T`, producing a `(Qty T u)`. The unit `u`
  is a compile-time value; `(Qty.of 5.0 metre)` is a `(Qty Float64 metre)` whose erased value is
  `5.0`.
- `(Qty.value q)` recovers the underlying numeric value, **discarding the unit** — the explicit exit
  from the dimensional layer, the analogue of widening a refinement to its base type
  (verification-layers.md #Refinement Coercions Are Checked: "Widening … MUST require no check"). It
  is the only way a unit leaves a value, and it is always explicit.
- A dimensionless quantity `(Qty T Unit.one)` and the bare numeric `T` are the **same erased value**
  but are **distinct static types**: crossing between them is explicit (`Qty.of x Unit.one` /
  `Qty.value q`), never an implicit coercion — the same discipline the numeric core applies to width
  and signedness (no silent promotion, numeric-model.md).

## How arithmetic composes dimensions

Dimensional composition is fixed by the operation, per units-of-measure.md #Dimensional Mismatch Is An
Error ("An operation that derives a dimension MUST produce the dimension the operation's rule defines
rather than discard dimensional information"):

| Operation on `(Qty T a)` and `(Qty T b)` | Dimensional rule | Result |
|---|---|---|
| `(+ p q)`, `(- p q)` | dimensions MUST be equal (`a` = `b`) | `(Qty T a)` |
| `(< p q)`, `(> p q)`, `(<= …)`, `(>= …)`, `(= …)` | dimensions MUST be equal | `Bool` |
| `(* p q)` | dimensions multiply | `(Qty T (Unit.* a b))` |
| `(/ p q)` | dimensions divide | `(Qty T (Unit./ a b))` |
| `(Qty.pow p n)` (`n` a compile-time integer) | dimension raised to `n` | `(Qty T (Unit.^ a n))` |

The **underlying numeric type `T` obeys the numeric core unchanged**: `(+ p q)` requires `p` and `q`
to have the *same* `T` just as bare numeric addition does (no silent promotion between `Int64` and
`Float64`, numeric-model.md), and the numeric operation that actually runs is the plain `T` operation
on the erased values. The unit layer adds one obligation on top — that the *dimensions* also agree for
`+`/`-`/comparison, and compose by the group operation for `*`/`/`/`pow` — and contributes **nothing**
to the emitted arithmetic.

Multiplying by a bare (dimensionless) numeric scalar is the ordinary product with `Unit.one`, so
scaling a quantity by a constant keeps its dimension: `(* (Qty.of 2.0 metre) (Qty.of 3.0 Unit.one))`
is `(Qty Float64 metre)` with value `6.0`.

## The dimensional mismatch is CDZ0501, at compile time

Combining quantities of incompatible dimension is rejected at compile time with **`CDZ0501`**
(options/diagnostics-schema/, units-of-measure.md #Dimensional Mismatch Is An Error). The rejection
covers:

- adding, subtracting, or comparing quantities of unlike dimension —
  `(+ (Qty.of 1.0 metre) (Qty.of 1.0 second))`;
- annotating a quantity at a dimension the expression does not derive —
  `(: (* (Qty.of 2.0 metre) (Qty.of 3.0 metre)) (Qty Float64 metre))` (the product is `metre²`, not
  `metre`), which is the dimensional specialization of the annotation-conflicts rejection
  (`CDZ0203` names the general case; `CDZ0501` names it when the conflict is dimensional).

There is **no runtime trap** for a dimensional error: units are erased before the program runs, so a
dimensional inconsistency can only be a compile-time event. This is why `CDZ0501` sits in the
verification-layer band (`CDZ05xx`), not among the numeric traps.

## Erasure — what crosses the boundary

`(Qty T u)` **erases to `T`** before emission (units-of-measure.md #Dimensions Are Checked Then
Erased; the refinement-erases-to-its-base-type discipline, verification-layers.md). Concretely:

- The emitted value of a `(Qty T u)` is exactly the emitted value of its underlying `T` — same
  canonical byte form, same boundary representation. `(Qty.of 5.0 metre)` and the bare `5.0` are
  **byte-identical** in the emitted component (they differ only in the erased static type the corpus
  records in `(: … Type)`).
- No unit, base-dimension name, or exponent map appears anywhere in the emitted component; the group
  algebra is entirely a compile-time computation.
- A `(Qty T u)` therefore has **no boundary representation of its own** — it is an internal-only static
  type, like a non-aliased integer width `(UInt 48)`. A quantity crossing an exported or imported
  signature crosses as its underlying `T` (component-abi.md #A type that has no defined boundary
  representation MUST NOT appear in an exported or imported signature); the dimensional contract on a
  boundary is documentation and compile-time checking on the Cadenza side, not a wire distinction.
- Because erasure is total, a component derived from well-dimensioned source with the capability
  **included** is byte-identical to one derived with it **excluded** — dimensional discharge does not
  change emitted bytes (verification-layers.md #Discharge Does Not Change Emitted Bytes). The capability
  can only *reject more programs*, never change the meaning of one it accepts.

## Why these choices, against the north star

- **A compile-time-value unit, not bespoke syntax.** Because Cadenza's type constructors are already
  compile-time functions from compile-time values to a type — the `(Int N)` integers are indexed by a
  compile-time natural — a quantity type `(Qty T u)` indexed by a compile-time *unit* needs no new core
  syntax and no dependent types: a unit is an ordinary value the compiler evaluates at compile time,
  exactly as it evaluates `N` in `(UInt N)`. The whole layer is "one more compile-time-value-indexed
  type constructor," not a special case in the type checker.
- **A free abelian group is the right and minimal algebra.** Dimensional analysis *is* a free abelian
  group over base dimensions; encoding units as `(base ↦ integer-exponent)` maps makes dimensional
  equality a canonical-form comparison (a pure, decidable, solver-free compile-time check) and makes
  derived units (`velocity` = `length·time⁻¹`) fall out of the group operations rather than needing to
  be enumerated. This is the model F# units of measure use, and it is why the check "costs nothing" —
  it is a finite exponent-map comparison, not a constraint search.
- **Erasure keeps it off the byte path.** A unit is checked then erased, so it satisfies
  meaning-preservation and discharge-does-not-change-bytes by construction: the numeric core is
  untouched, and a program pays only compile time, never runtime, for the whole apparatus. This is the
  literal reason the capability "survives the clean room" — it buys a class of verified correctness for
  zero runtime cost.
- **No implicit dimensionless coercion.** Keeping `(Qty T Unit.one)` and bare `T` distinct static types
  (crossed only by explicit `Qty.of` / `Qty.value`) mirrors the numeric core's no-silent-promotion
  stance: the same reason `Int64` does not silently become `Float64`, a dimensionless quantity does not
  silently become a raw number — an agent and a verifier see every crossing in the source.

## Relationship to the numeric model and other layers

- **Numeric core (numeric-model.md, `options/numeric-model/`).** Units layer *over* the numeric core
  and never alter it: the underlying `T` keeps its widths, overflow behavior, and no-promotion rule
  exactly, and the running arithmetic is the plain `T` operation on erased values. `(Qty T u)` adds a
  dimensional obligation; it changes no numeric byte form (units-of-measure.md #Dimensional Analysis
  Does Not Alter The Numeric Core; numeric-model.md #Relationship To Units Of Measure).
- **Refinement layer (verification-layers.md).** A unit is precisely a refinement whose predicate is
  "carries dimension `u`" and whose base type is `T`; it erases to its base type like any refinement,
  and crossing out of it (`Qty.value`) is the widening that requires no check. Dimensional analysis is
  the first verification layer a generation realizes because it is the one with a purely syntactic,
  solver-free discharge.
- **Symbols (`options/symbol-interning/`).** Base dimensions are named by `Symbol`s, so a program
  declares its own base dimensions and the layer fixes the algebra, not a fixed unit vocabulary. A
  build's prelude MAY define the SI base dimensions and common derived units as ordinary definitions.
