# Emitting a component that imports is a fixed envelope around a variable core module

*2026-07-05*

**What happened.** The compiler must emit every component byte itself — the goal is to compile
Cadenza with only a wasm runtime present, so no external tool (`wasm-tools`, `wac`, cargo-component)
may run at compile time. Until M2, every emitted component was self-contained (zero imports), and
the existing technique for that was already the right one: derive a byte-exact reference component
once at the dev desk with `wasm-tools` (author `.wat`, validate, strip the provenance custom
sections), then split it into fixed constant byte-arrays baked into the compiler; at compile time
the compiler concatenates those constants around a core module it builds byte-by-byte. M2 needed the
first component that *imports* — a program importing the value-heap runtime `cadenza:runtime/heap`.
The same technique carried over cleanly, with three concrete facts that a component-with-an-import
forces and a self-contained one does not:

1. **The variable part is only the core module.** Everything the component model adds around the
   core — the import declaration of the interface, the `canon lower` of each imported function, the
   core-instance instantiation that threads the lowered functions back in, the `canon lift` of the
   result, and the export — is program-independent. So the reference splits into a fixed **HEAD**
   (magic + import + lowers) and a fixed **TAIL** (instance + aliases + lift + export), with the
   compiler-built core module between them. The split point is found by locating the embedded core
   module's `\0asm` signature and its section framing; reassembly is verified byte-for-byte against
   the stripped reference.

2. **Imports occupy the low index space, so every defined function's index shifts by a fixed base.**
   A wasm module's imported functions take indices `0..n_imports`; the module's own defined
   functions start at `n_imports`. The runtime-compound module imports 11 heap functions and then
   defines 4 fixed helper functions (a bump `cabi_realloc`, an unsigned-decimal writer, a signed
   `itoa`, and the type-directed renderer) before the program's own functions — so a user function's
   wasm index is `15 + its ordinary index`, and `main` (ordinary index 0) is at 15. This is handled
   by one `call_base` offset added at every emitted `call` site (user calls and the
   overflow-checked-arithmetic helper calls alike); it is `0` for the self-contained scalar shape
   (which stays byte-identical) and `15` for the runtime-compound shape. The offset shifts only
   emitted call *bytes* — a function's result *kind* and the reachability graph are invariant to it,
   so kinds and dead-code elimination can be computed once at base 0 and the bodies re-emitted at
   the real base without recomputing anything.

3. **The fixed helper bodies bake their own call targets, so they pin the layout.** The renderer
   calls the accessors (`tag-of`, `get-int`, …) at their absolute import indices and recurses to
   itself and `itoa` at their fixed defined indices; the `run` body calls `main` at the base index
   and the renderer at its fixed index. Those baked indices are correct for *any* program as long as
   the layout above holds (fixed helpers first, then user functions with `main` at the base). That
   invariant is the contract between the baked bytes and the generated bytes, and it is worth stating
   wherever the constants live.

**Why.** A component is a stable, content-addressed artifact whose bytes must be a pure function of
source; letting a tool complete the bytes would put a second, unversioned producer in the
derivation and break reproducibility (and would require that tool to exist wherever Cadenza runs,
which contradicts "compile with only a wasm runtime"). Baking a validated reference makes the tool a
*dev-desk oracle* — it shapes the constants once, off the compile path — rather than a dependency.
And the reason the technique generalizes from zero-import to one-import components with so little
change is that the component-model surround is genuinely program-independent: the only thing that
varies with the program is the core module's code, which the compiler was already building by hand.

**The requirement it drove.** No new normative requirement — this is engineering technique for
realizing existing ones. It is how `spec/contracts/reproducible-derivation.md` §"Derivation Is A
Function Of Source And Toolchain" is met for a component that imports (the compiler emits the bytes;
no compile-time tool), and how `spec/contracts/component-abi.md` §"The Value-Heap Runtime Crosses By
A Well-Known Import" is realized in the emitter. Recorded so the next contributor — and eventually
the self-hosted compiler that must re-derive this in Cadenza — inherits the split-envelope technique
and the import-index-shift discipline rather than rediscovering them. Composes with
[the value-heap runtime is a shared component](./2026-07-05-the-value-heap-runtime-is-a-shared-component.md)
and [the runtime is name-free](./2026-07-05-the-runtime-is-name-free-rendering-is-type-directed.md).
