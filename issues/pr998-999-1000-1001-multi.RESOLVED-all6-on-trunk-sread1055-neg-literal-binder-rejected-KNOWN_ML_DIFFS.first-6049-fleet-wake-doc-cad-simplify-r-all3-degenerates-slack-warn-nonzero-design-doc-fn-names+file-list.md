## sread.cdz:861 (PR#998, id 3695500665) → v-compiler-ml — REJECT-PATH GAP

blame `fa92fdc0e` "compiler-ml: reject a refutable literal in a let binder (reject-path gap 2)". The guard
(sread.cdz:858) rejects a DIGIT-LED binder: `(if is-digit(char-at(nm, 0)) then unsupported…)`. But a
NEGATIVE numeric literal `-1` starts with `-` (not a digit), so `is-digit` is false → `-1` is accepted as
a name → `NLet(name-id("-1"), …)`, contradicting the "identifier-only binder" rule (a negative literal in
binder position is a refutable pattern, should decline like the digit case). Extend the guard to also
reject a leading `-` followed by a digit (or, more general: reject any binder that parses as a numeric
literal). Reject-path completeness.
