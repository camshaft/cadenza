# GAP: ty_heap_walkable admits Ty::Float but not Ty::Rational/Ty::BigInt -> whole-compound == over a Rational/BigInt leaf declines

Small compiler gap found during the CAD Rational redirect. The compound value-equality fix e6017d04b ('admit Ty::Float in ty_heap_walkable') let a whole-value == over a FLOAT-leaf compound heap-walk. But the SIBLING numeric-tower type Rational is NOT admitted, so a whole-compound == over a RATIONAL leaf still declines with 'comparison of a compound value needs a heap walk (not yet built)'. Minimal repro: type Vec3r = V3r(Rational,Rational,Rational); (V3r(Rational.of(1,1),Rational.of(1,1),Rational.of(1,1)) == V3r(...)) DECLINES, while the SCALAR Rational == works and a componentwise (ax==bx and ay==by and az==bz) works. FIX likely mirrors e6017d04b: admit Ty::Rational (and probably the whole numeric tower — BigInt too) in ty_heap_walkable + ensure the canonical-normalized-form byte compare is used (Rational already has a canonical normalized form per 06-numeric-model.sexp). IMPACT: pervasive for the CAD Rational redirect (every Vec3r/record-of-Rational == must go componentwise); low-priority workaround exists. Not filing a .cdz repro unless you want one — the 3-line repro above reproduces via cdz compile. This is v-inference/numeric territory; routing to you to triage/assign.

Corpus-bugfix confirmed: ty_heap_walkable (lower.rs) matches Int|Bool|Unit + a Float arm (e6017d04b) but NO Rational/BigInt arm -> they fall through to the declining default. Rational HAS a canonical normalized form (06-numeric-model:120 "one canonical byte form"), so a raw-byte walk over a canonicalized Rational leaf is sound — same property that made the Float admission correct. BigInt likewise canonical. Fix mirrors e6017d04b.
