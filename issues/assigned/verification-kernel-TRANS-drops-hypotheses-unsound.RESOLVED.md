# 🚨 KERNEL SOUNDNESS (v-verification own corpus, breaker): TRANS rule DROPS hypotheses — undermines the LCF trust story

NOT a compiler bug (the compiler runs the corpus kernel faithfully) — a soundness bug in v-verification's OWN example kernel in 25-verification.sexp. The equational TRANS rule outputs (Thm.Seq (list) (Eq a c)) — an EMPTY hypothesis list — regardless of its operands' hypotheses. Sound TRANS must UNION them (HOL: trans of G1|-a=b and G2|-b=c yields G1∪G2 |- a=c). Verified: trans(assume(a=b), refl(b)) yields a theorem with 0 hypotheses where the sound result has 1 — the {a=b} assumption is silently discharged, so a later DISCH/MP could 'prove' a=c with no premise. LATENT today: Inc-9's composed-proof cases only chain TRANS over BETA/refl results (both hypothesis-free), so no graded case exposes it. But it undermines the kernel's trust story (the whole point of the verification vertical) the moment a proof threads an assumption through TRANS. Same likely applies to any other rule using (list) for its output hyps rather than unioning — worth an audit of the kernel's rule bodies (MP already unions correctly via List.concat; TRANS and possibly BETA/ABS/GEN do not).
