# reducer-onresponse-cdz — a Cadenza reducer that reacts on the `on-response` path

`reducer.cdz` (authored by v-platform) exercises the `on-response` entry point: when a response is delivered,
it reads the response envelope's correlation — its `contract` and continuation `token` — and emits one
request echoing them back. It deliberately does not touch `answer` (the `result<payload, error>`), so it
needs no result match: it is the minimal observable proof that the response envelope reaches the guest and
its typed fields flow through. `on-message` and `on-notification` are inert (continue, no requests); the
fixture drives the response path by injecting a response.

Like `reducer-identity-cdz`, it targets the shared `world.wit` via the external `KIND_WIT_WORLD` artifact
`reducer-world.bin` (so the derived `on-response` parameter resolves against the real `response` record
`{contract, token, answer}`), generated by `cdz-world-artifact` from the single source of truth. The nix
flake auto-enumerates it (`guests/reducer-world/reducer-onresponse-cdz/reducer.cdz`) into `harnessPrograms`
and builds it:

```
cdz compile reducer.cdz wit-world:reducer-world=reducer-world.bin --target wasm
```

The component imports `cadenza:runtime/heap@…` and exports the typed `cadenza:platform/guest`
(on-message/on-response/on-notification → step); it performs no host import.

The paired harness run (spawn + inject a response, assert the guest reacts) is authored by v-platform-itest
against the response-delivery path added in #3146 (`DeliveryEvent::Response`).
