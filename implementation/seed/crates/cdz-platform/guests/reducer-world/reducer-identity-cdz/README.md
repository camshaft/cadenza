# reducer-identity-cdz — a Cadenza reducer that CALLS a host import

`reducer.cdz` (authored by v-platform) is the echo reducer with one change: `on-message` wraps its body in
`host identity in { … }` and stamps the echoed request's token with `identity.id()` — the reducer's own id,
a compound `list<u8>` host result. This exercises the shared-allocator slice (#3121): a host op with a
compound result needs a `realloc` available at canon-lower time (the `mem` module provides memory + realloc,
the wrapper imports both). It proves a host value flows through the guest and back.

Unlike `reducer-echo-cdz` (which types its export with a small inline `(world …)`), this reducer CALLS a
host import, so its world must declare the `cadenza:platform/identity` IMPORT — which the inline export form
can't. It therefore consumes the external `KIND_WIT_WORLD` artifact `reducer-world.bin` (generated by
`cargo xtask world-artifact` from the shared `cdz-platform/wit/world.wit`, the single source of truth). The
nix flake's `mkCadenzaGuest { witWorld = "${worldArtifacts}/reducer-world.bin"; }` wires it:

```
cdz compile reducer.cdz wit-world:reducer-world=reducer-world.bin --component-name cadenza:platform/guest --target wasm
```

The component imports `cadenza:platform/identity` + `cadenza:runtime/heap@…` and exports the typed
`cadenza:platform/guest` (on-message/on-response/on-notification → step). Registered in `harnessPrograms`
as `reducer-identity-cdz`; `harness-runs/reducer-identity-cdz-echo.ml` spawns it + delivers a message
(the host wires `identity` for a non-pure reducer, so it composes + drives like the echo).
